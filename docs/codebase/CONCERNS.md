| C-1  | **Critical**                 | Backups are encrypted with the device-bound Keystore key. After reinstall or on a new device, `decrypt()` fails and returns the Base64 ciphertext, which is then **imported as the password**. The unit test `importFromJson handles legacy plaintext JSON` locks in that fallback. | `JsonExportImport.kt`, `CryptoManager.decrypt`, `JsonExportImportTest.kt`                           | Silent loss of every password in a restored backup                                                    | Password-based backup encryption (PBKDF2/Argon2 → AES-GCM) with a versioned format. Reject undecryptable entries explicitly |
| C-2  | High                         | Crypto fails open: `encrypt()` returns plaintext on any exception, and `decrypt()` returns its input                                                                                                                                                                                | `CryptoManager.kt:53-70`, `72-86`                                                                   | Plaintext silently written to DB/backup; corrupted data shown as a password                           | Throw typed errors, surface them in the UI, and add a format/version marker to distinguish legacy plaintext                 |
| C-3  | High                         | `site_name`, `username`, `url`, `notes` stored and exported in plaintext                                                                                                                                                                                                            | `PasswordEntity.kt`, `PasswordRepository.kt`, `JsonExportImport.kt`                                 | Notes often hold recovery codes. Readable on rooted/forensic access or from backup files              | Encrypt all sensitive fields, or use full-DB encryption                                                                     |
| C-4  | High                         | No app lock. The Keystore key doesn't require user authentication                                                                                                                                                                                                                   | `CryptoManager.createSecretKey` (no `setUserAuthenticationRequired`), no `BiometricPrompt` anywhere | Anyone with the unlocked phone can read the vault                                                     | BiometricPrompt / device-credential gate on launch and resume                                                               |
