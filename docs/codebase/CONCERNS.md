## 1) Open Risks (Prioritized)

No open critical or high risks identified by the independent authentication reviews and the 2026-10-10 verification. API 33 native retesting confirms the rapid launcher-return timing correction, including pause/resume without stop/start. Coverage outside API 33, physical biometric hardware, and real process-death behavior remains unverified.

The ten risks from the 2026-09-18 audit (`C-1`…`C-10`: device-bound fail-open backups, fail-open crypto, plaintext metadata at rest, no app lock, no Room migration strategy, OS backup/D2D copying the vault, non-atomic import without dedupe, untyped one-shot events, silent save/delete errors, and the `@RequiresApi(P)` clipboard workaround) are all fixed. See `CHANGELOG.md` and the roadmap milestones for what shipped.

The independent review of `:feature:autofill` on 2026-11-10 found two save bugs that lost data, four unlock problems, and five more issues in frame matching, session length, two-step saves, the picker, and the Settings service row. All of them are fixed (see `CHANGELOG.md`). Device QA that hasn't been run yet is roadmap EN-7.2c.

The in-app update (EN-08 part 2) had device QA on 2026-11-11 with release builds signed by the debug key and a local feed (`-Pkupass.updateFeedUrl`, `app/src/qaFeed/`). On API 28 the unknown-apps trip kept the process, the system confirmation appeared, cancelling it gave the failure dialog, and Try again installed the update. On API 37 the update installed with no prompt; Play Protect showed and closed its own notice. Both kept the vault entry and showed `3.1.0-beta.2`. Android 17 offers "Always allow" or "Ask every time" for installing apps; under the default "Ask every time" Kupass asks for the permission first. Later, closing, the offline failure with the browser fallback, and the Settings switch also worked. `v3.1.0-beta.1` was published with the release key on 2026-11-11. Open: updating to `beta.2` in the app on a phone, the check at every open (changed after this QA), and API 31-36.

## 3) Security Concerns

Current policy uses an activity-local authenticated account session until the configured background timeout; entry/account-bound grants still protect destination creation. Export always needs fresh native authentication. Neither session status nor grants are persisted. The provided Google CSV passed parser/ViewModel checks and real API 33 SAF import as two accounts; the reported phone failure was not reproduced. Provider-read and repository/crypto errors now have distinct non-secret messages. No real CSV contents or credentials were added to the repository.

Controls: fail-closed AES-GCM (`kp2:`) on every field, portable password-based backups, UI-level per-account and export authentication, Room migrations, OS backup/D2D exclusions, `FLAG_SECURE`, and only the launcher Activity exported. Final verification on dependency base `38717b6`, after the P1/P2 and rapid-return corrections, passed serial formatting, detekt (0 findings and 0 compiler-analysis errors), all 107 JVM/Robolectric tests, lint (0 errors, 47 warnings), and debug assembly on 2026-10-10. The generated-`BuildConfig` diagnostics from the earlier run are resolved by the merged classpath fix. API 33 native checks passed rapid and settled launcher returns, detail/editor expiry, native PIN authentication and rotation, fresh account/export challenges, denied-auth lock screens, and an encrypted export through the real SAF picker under Immediate timeout. See TESTING.md for the remaining coverage limits.

**Reviewer corrections:** the process-wide timer was removed from `AppContainer`; each activity-retained controller privately constructs its timer alongside its grants, with owner-local exemptions. Independent review confirmed this closes the original cross-activity bypass. The prompt test double models a retained session and CURRENT callback per `ViewModelStore`. Rotation, cancelled-session completion, software dialog ordering, rapid-return revocation and single-count native exemptions pass. The double's retired-event filtering remains a modeled native contract, not hardware or AndroidX-internal proof; native results apply only to the tested API 33 emulator.

Public list/search/tabs/create/import/delete confirmation are intentional product scope. The existing repository/Home pipeline still decrypts list/search fields in process memory; per-entry UI authorization is not a Keystore or repository encryption boundary. No auth grants are persisted or placed in `AppContainer`.

The combined auth/backup branch subsequently passed serial full verification, including the independent-review fidelity/draining-request corrections, with 142 tests in 17 suites, zero failures/errors/skips, zero detekt findings/compiler diagnostics, zero lint errors and 47 warnings. Export retains request-bound consent before vault/provider access; `.kupass` export and strict legacy JSON/Google CSV import share synchronous busy guards, and pending or cancelled-but-draining native export requests block import. Editing imported entries preserves username/password/note formatting. This verification adds no native-device coverage beyond the auth APK's API 33 run above.

## 4) Performance and Size Concerns

The UI/import revision replaces accordion headers with regular badged rows and a public ID-routed group page. Group state saves only an anchor row ID; names, URLs, credentials and authorization grants are not saved. CSV validation now tolerates common header/encoding/line-ending variants while still rejecting malformed credentials before writes. These changes do not alter the Room schema, backup encryption format, or entry/export authentication boundary.
